۱. هدف این سند

هدف این سند این است که هر توسعه‌دهنده بتواند یک پلاگین کامل برای سیستم GeoChat تولید کند؛ پلاگینی که توسط کرنل کشف، ثبت، Route، اجرا و در نهایت به پاسخ مکانی تبدیل شود.

اصل بسیار مهم معماری: کرنل نباید برای اضافه شدن قابلیت‌های جدید تغییر کند. تمام پردازش‌های تخصصی GIS، سنجش از دور، تحلیل رستر، تحلیل بردار، اتصال به دیتابیس و تولید خروجی باید در پلاگین‌ها انجام شود.

این سند بر اساس SDK فعلی GeoChat نوشته شده است که شامل این اجزاست:

  • @capability برای معرفی یک تابع به عنوان قابلیت قابل اجرا
  • auto_collect برای ساخت شیء نهایی پلاگین
  • RasterIn و RasterOut برای ورودی/خروجی رستری
  • VectorIn و VectorOut برای ورودی/خروجی برداری
  • SDKStepHandler برای تبدیل خودکار PlanStep به فراخوانی تابع پلاگین
  • SDKPlanner برای ساخت PlanStep از QueryIR
  • SDKResultFusion برای تبدیل artifactهای خروجی به GeoResponse

۲. جایگاه پلاگین در معماری GeoChat

سیستم GeoChat از یک کرنل مرکزی و مجموعه‌ای از پلاگین‌ها تشکیل شده است. کرنل مسئول orchestration، registry، routing، اجرای DAG، trace و response است. اما خود کرنل نباید عملیات تخصصی مکانی انجام دهد.

User Query Query Parser Router Planner PlanStep StepHandler Plugin Function ExecutionArtifact ResultFusion GeoResponse
لایه مسئولیت آیا در پلاگین نوشته می‌شود؟
Kernel اجرای pipeline، مدیریت registry، routing، trace، audit و اجرای plan خیر
SDK ساده‌سازی تولید پلاگین، تبدیل ورودی/خروجی و ثبت خودکار capability استفاده می‌شود
Plugin انجام پردازش تخصصی مثل NDVI، Buffer، Spatial Join، Raster Clip و غیره بله
External Libraries کتابخانه‌هایی مثل rasterio، geopandas، shapely، numpy، scipy فقط در پلاگین
هیچ کتابخانه سنگین GIS مثل rasterio، geopandas یا shapely نباید به عنوان وابستگی ضروری کرنل در نظر گرفته شود. این کتابخانه‌ها باید فقط در محیط پلاگین نصب و استفاده شوند.

۳. مفاهیم اصلی SDK

۳.۱. Capability چیست؟

Capability یعنی یک توانایی مشخص سیستم که قابل route و اجرا باشد. مثلاً:

  • بارگذاری رستر محلی
  • محاسبه NDVI
  • ایجاد Buffer
  • محاسبه فاصله
  • استخراج آمار زونال

در SDK، هر تابعی که با @capability تزئین شود، به عنوان یک قابلیت قابل ثبت شناخته می‌شود.

۳.۲. Plugin چیست؟

پلاگین یک بسته منطقی از یک یا چند capability است. هر فایل پلاگین باید در انتها یک متغیر سراسری به نام PLUGIN داشته باشد. 

PLUGIN = auto_collect(
    id="local_raster_loader",
    version="1.0.0",
    name="Local Raster Loader",
    description="Load local raster files as raster references",
    author="GeoChat Platform Team",
    permissions=["read_raster"],
)

۳.۳. ExecutionArtifact چیست؟

خروجی واقعی اجرای هر Step در کرنل یک ExecutionArtifact است. اما توسعه‌دهنده پلاگین معمولاً مستقیماً با آن کار نمی‌کند. SDK خروجی‌های زیر را خودکار تبدیل می‌کند:

خروجی تابع پلاگین تبدیل خودکار به artifact کاربرد
RasterOut kind="raster_ref" خروجی رستری، مسیر فایل GeoTIFF یا raster reference
VectorOut kind="features" خروجی برداری GeoJSON Featureها
ExecutionArtifact بدون تغییر برای توسعه‌دهندگان پیشرفته
هر مقدار دیگر kind="payload" خروجی عمومی مثل dict، عدد، متن و غیره

۴. چرخه عمر پلاگین در سیستم

  1. توسعه‌دهنده یک فایل Python در پوشه plugins/ می‌سازد.
  2. توابع پردازشی را با @capability مشخص می‌کند.
  3. در انتهای فایل با auto_collect یک PLUGIN می‌سازد.
  4. PluginLoader کرنل فایل را کشف و import می‌کند.
  5. SDKPlugin همه capabilityها را ثبت می‌کند.
  6. برای هر capability، یک Planner و StepHandler خودکار ساخته می‌شود.
  7. در زمان درخواست کاربر، Router یا Planner قابلیت مناسب را انتخاب می‌کند.
  8. StepHandler ورودی‌ها را تبدیل و تابع پلاگین را اجرا می‌کند.
  9. خروجی تابع به ExecutionArtifact تبدیل می‌شود.
  10. ResultFusion خروجی را به GeoResponse تبدیل می‌کند.
نتیجه مهم: برای بیشتر پلاگین‌ها لازم نیست شما Planner، StepHandler یا Fusion دستی بنویسید. SDK این کارها را به صورت خودکار انجام می‌دهد.

۶. نوشتن Capability با دکوریتور

دکوریتور @capability مهم‌ترین بخش تولید پلاگین است. این دکوریتور تابع شما را به کرنل معرفی می‌کند.

امضای دکوریتور

@capability(
    name: str,
    keywords: list[str] | None = None,
    description: str | None = None,
    required_inputs: list[str] | None = None,
    optional_inputs: list[str] | None = None,
    output_kind: str | None = None,
    permissions: list[Any] | None = None,
    metadata: dict[str, Any] | None = None,
)

توضیح فیلدها

فیلد اجباری؟ توضیح مثال
name بله نام یکتای capability درون پلاگین load_local_raster
keywords خیر، ولی بسیار مهم کلمات کلیدی برای route شدن query ["raster", "geotiff", "بارگذاری رستر"]
description خیر توضیح انسانی برای قابلیت Load local GeoTIFF raster
required_inputs خیر نام ورودی‌های ضروری ["path"]
optional_inputs خیر نام ورودی‌های اختیاری ["band"]
output_kind خیر نوع خروجی منطقی capability "raster" یا "vector"
permissions خیر مجوزهای مورد نیاز capability ["read_raster"]
metadata خیر اطلاعات اضافی برای routing یا documentation {"category": "data_io"}

مثال ساده

from geochat_sdk import capability, RasterOut

@capability(
    name="load_local_raster",
    keywords=["raster", "geotiff", "tif", "بارگذاری رستر"],
    required_inputs=["path"],
    output_kind="raster",
    description="Load a local raster file and return a raster reference",
    permissions=["read_raster"],
)
def load_local_raster(path: str) -> RasterOut:
    return RasterOut(
        path=path,
        metadata={"source": "local_file"}
    )
نام پارامترهای تابع باید با required_inputs و پارامترهایی که Planner می‌سازد هماهنگ باشد. اگر تابع شما path می‌خواهد، باید در plan نیز پارامتر path وجود داشته باشد.

۷. ثبت نهایی پلاگین با auto_collect

در انتهای هر فایل پلاگین باید PLUGIN ساخته شود. PluginLoader کرنل معمولاً به دنبال همین متغیر می‌گردد. 

PLUGIN = auto_collect(
    id="local_raster_loader",
    version="1.0.0",
    name="Local Raster Loader",
    description="Load local raster files",
    author="GeoChat Platform Team",
    permissions=["read_raster"],
)

قانون طلایی auto_collect

auto_collect باید همیشه بعد از تمام capabilityها در انتهای فایل قرار بگیرد. چون دکوریتور @capability ابتدا تابع‌ها را در لیست داخلی SDK ثبت می‌کند و سپس auto_collect آن‌ها را جمع‌آوری می‌کند.

ساختار صحیح

from geochat_sdk import capability, auto_collect

@capability(name="first_capability")
def first_capability():
    pass

@capability(name="second_capability")
def second_capability():
    pass

PLUGIN = auto_collect(
    id="my_plugin",
    version="1.0.0",
)

ساختار غلط

from geochat_sdk import capability, auto_collect

PLUGIN = auto_collect(
    id="my_plugin",
    version="1.0.0",
)

@capability(name="first_capability")
def first_capability():
    pass

در حالت غلط، capability بعد از auto_collect تعریف شده و بنابراین در پلاگین ثبت نمی‌شود.

نکته سازگاری Import

اگر در نسخه‌ای از SDK، auto_collect از مسیر اصلی export نشده بود، می‌توان از الگوی زیر استفاده کرد: 

try:
    from geochat_sdk import capability, auto_collect, RasterIn, RasterOut, VectorIn, VectorOut
except ImportError:
    from geochat_sdk.decorators import capability
    from geochat_sdk.plugin import auto_collect
    from geochat_sdk.types import RasterIn, RasterOut, VectorIn, VectorOut

۸. مدیریت ورودی و خروجی در SDK

۸.۱. ورودی‌های ساده

پارامترهایی مثل path: str، radius_m: float، limit: int از step.parameters خوانده می‌شوند. 

@capability(
    name="calculate_buffer",
    required_inputs=["distance_m"],
    output_kind="vector",
)
def calculate_buffer(distance_m: float) -> VectorOut:
    ...

۸.۲. ورودی رستری با RasterIn

اگر پارامتر تابع از نوع RasterIn باشد، SDK تلاش می‌کند یک artifact از نوع raster_ref پیدا کند و آن را به RasterIn تبدیل کند. 

from geochat_sdk import RasterIn, RasterOut

@capability(
    name="normalize_raster",
    required_inputs=["raster"],
    output_kind="raster",
)
def normalize_raster(raster: RasterIn) -> RasterOut:
    arr = raster.read_numpy(1)
    profile = raster.get_profile()

    normalized = (arr - arr.min()) / (arr.max() - arr.min())

    return RasterOut.from_numpy(
        data=normalized,
        profile=profile,
        output_path="output/normalized.tif",
    )

۸.۳. ورودی برداری با VectorIn

اگر پارامتر تابع از نوع VectorIn باشد، SDK یک artifact از نوع features یا vector را به آن تبدیل می‌کند. 

from geochat_sdk import VectorIn, VectorOut

@capability(
    name="filter_features",
    required_inputs=["features"],
    output_kind="vector",
)
def filter_features(features: VectorIn) -> VectorOut:
    selected = []
    for feature in features.features:
        props = feature.get("properties", {})
        if props.get("population", 0) > 1000:
            selected.append(feature)

    return VectorOut(
        features=selected,
        metadata={"filter": "population > 1000"},
    )

۸.۴. خروجی RasterOut

RasterOut برای خروجی‌هایی استفاده می‌شود که یک مسیر فایل رستر تولید می‌کنند. این خروجی به artifact با kind="raster_ref" تبدیل می‌شود. 

return RasterOut(
    path="output/result.tif",
    metadata={
        "crs": "EPSG:4326",
        "description": "NDVI result",
    },
)

۸.۵. خروجی VectorOut

VectorOut برای خروجی‌های برداری بر اساس GeoJSON Feature استفاده می‌شود. 

return VectorOut(
    features=[
        {
            "type": "Feature",
            "geometry": {"type": "Point", "coordinates": [51.4, 35.7]},
            "properties": {"name": "sample"},
        }
    ],
    metadata={"count": 1},
)

۸.۶. تزریق ExecutionContext

اگر پارامتری به نام context داشته باشید یا annotation آن ExecutionContext باشد، SDK آن را خودکار تزریق می‌کند. 

from geochat_kernel.runtime.execution_context import ExecutionContext

@capability(name="context_aware_tool")
def context_aware_tool(context: ExecutionContext) -> dict:
    return {
        "request_id": context.request_id,
        "metadata": context.metadata,
    }

۹. Routing و انتخاب پلاگین

در SDK فعلی، Planner تولیدشده توسط SDK از دو مسیر اصلی match می‌شود:

  1. اگر در context.metadata["routing"]["selected"] نام capability انتخاب شده باشد، امتیاز match برابر 1.0 است.
  2. اگر یکی از keywords در متن خام query وجود داشته باشد، امتیاز match برابر 0.8 است.
  3. در غیر این صورت امتیاز 0.0 است.

اهمیت Keywords

انتخاب keywordهای خوب و چندزبانه برای پلاگین بسیار مهم است. چون برای MVP، keyword matching یکی از پایه‌های اصلی route شدن پلاگین است.

مثال keyword خوب برای local_raster_loader

keywords=[
    "raster",
    "geotiff",
    "tif",
    "tiff",
    "load raster",
    "local raster",
    "بارگذاری رستر",
    "خواندن رستر",
    "فایل رستر",
    "تصویر ماهواره‌ای",
]

مثال keyword ضعیف

keywords=["data", "file"]

این keywordها بیش از حد عمومی هستند و ممکن است route اشتباه ایجاد کنند.

۱۰.۱. قالب عمومی پلاگین

from __future__ import annotations

from typing import Any

try:
    from geochat_sdk import capability, auto_collect
except ImportError:
    from geochat_sdk.decorators import capability
    from geochat_sdk.plugin import auto_collect


@capability(
    name="my_capability",
    keywords=["keyword 1", "keyword 2"],
    required_inputs=["input_name"],
    optional_inputs=[],
    output_kind="payload",
    description="Describe what this capability does",
    permissions=["my_permission"],
    metadata={"category": "general"},
)
def my_capability(input_name: str) -> dict[str, Any]:
    if not input_name:
        raise ValueError("input_name is required")

    result = {
        "input": input_name,
        "status": "ok",
    }

    return result


PLUGIN = auto_collect(
    id="my_plugin",
    version="1.0.0",
    name="My Plugin",
    description="A standard GeoChat SDK plugin",
    author="GeoChat Plugin Team",
    permissions=["my_permission"],
)

۱۰.۲. قالب پلاگین رستری

from __future__ import annotations

from pathlib import Path

try:
    from geochat_sdk import capability, auto_collect, RasterIn, RasterOut
except ImportError:
    from geochat_sdk.decorators import capability
    from geochat_sdk.plugin import auto_collect
    from geochat_sdk.types import RasterIn, RasterOut


@capability(
    name="process_raster",
    keywords=["raster processing", "پردازش رستر"],
    required_inputs=["raster"],
    optional_inputs=["band"],
    output_kind="raster",
    description="Process a raster and produce a new raster output",
    permissions=["read_raster", "write_raster"],
    metadata={"category": "raster"},
)
def process_raster(raster: RasterIn, band: int = 1) -> RasterOut:
    arr = raster.read_numpy(band)
    profile = raster.get_profile()

    output_dir = Path("output")
    output_dir.mkdir(parents=True, exist_ok=True)

    result = arr

    return RasterOut.from_numpy(
        data=result,
        profile=profile,
        output_path=str(output_dir / "processed_raster.tif"),
    )


PLUGIN = auto_collect(
    id="raster_processing_plugin",
    version="1.0.0",
    name="Raster Processing Plugin",
    description="Standard raster processing plugin",
    author="GeoChat Plugin Team",
    permissions=["read_raster", "write_raster"],
)

۱۰.۳. قالب پلاگین برداری

from __future__ import annotations

try:
    from geochat_sdk import capability, auto_collect, VectorIn, VectorOut
except ImportError:
    from geochat_sdk.decorators import capability
    from geochat_sdk.plugin import auto_collect
    from geochat_sdk.types import VectorIn, VectorOut


@capability(
    name="process_vector",
    keywords=["vector processing", "پردازش بردار"],
    required_inputs=["features"],
    output_kind="vector",
    description="Process vector features and return new features",
    permissions=["read_vector", "write_vector"],
    metadata={"category": "vector"},
)
def process_vector(features: VectorIn) -> VectorOut:
    output_features = []

    for feature in features.features:
        props = dict(feature.get("properties") or {})
        props["processed"] = True

        output_features.append({
            "type": "Feature",
            "geometry": feature.get("geometry"),
            "properties": props,
        })

    return VectorOut(
        features=output_features,
        metadata={"count": len(output_features)},
    )


PLUGIN = auto_collect(
    id="vector_processing_plugin",
    version="1.0.0",
    name="Vector Processing Plugin",
    description="Standard vector processing plugin",
    author="GeoChat Plugin Team",
    permissions=["read_vector", "write_vector"],
)

۱۰.۴. قالب پلاگین ترکیبی Raster + Vector

from __future__ import annotations

try:
    from geochat_sdk import capability, auto_collect, RasterIn, VectorIn, VectorOut
except ImportError:
    from geochat_sdk.decorators import capability
    from geochat_sdk.plugin import auto_collect
    from geochat_sdk.types import RasterIn, VectorIn, VectorOut


@capability(
    name="raster_vector_analysis",
    keywords=["zonal statistics", "raster vector", "آمار زونال"],
    required_inputs=["raster", "zones"],
    output_kind="vector",
    description="Analyze raster values inside vector zones",
    permissions=["read_raster", "read_vector", "write_vector"],
    metadata={"category": "fusion"},
)
def raster_vector_analysis(raster: RasterIn, zones: VectorIn) -> VectorOut:
    # This is only a structure template.
    # Real implementation may use rasterio, rasterstats, geopandas, shapely.
    features = []

    for feature in zones.features:
        props = dict(feature.get("properties") or {})
        props["raster_analysis"] = "computed_placeholder"

        features.append({
            "type": "Feature",
            "geometry": feature.get("geometry"),
            "properties": props,
        })

    return VectorOut(
        features=features,
        metadata={
            "raster_path": raster.path,
            "zone_count": len(features),
        },
    )


PLUGIN = auto_collect(
    id="raster_vector_analysis_plugin",
    version="1.0.0",
    name="Raster Vector Analysis Plugin",
    description="Fusion plugin for raster and vector analysis",
    author="GeoChat Plugin Team",
    permissions=["read_raster", "read_vector", "write_vector"],

۱۱.۳. تست پلاگین رستری با فایل GeoTIFF موقت

from __future__ import annotations

import sys
from pathlib import Path

import numpy as np
import pytest
import rasterio
from rasterio.transform import from_origin

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

from plugins.local_raster_loader import load_local_raster, PLUGIN


@pytest.fixture
def sample_geotiff(tmp_path) -> str:
    path = tmp_path / "sample.tif"

    data = np.ones((1, 10, 10), dtype=np.uint8)
    transform = from_origin(50.0, 35.0, 0.01, 0.01)

    with rasterio.open(
        path,
        "w",
        driver="GTiff",
        height=10,
        width=10,
        count=1,
        dtype="uint8",
        crs="EPSG:4326",
        transform=transform,
    ) as dst:
        dst.write(data)

    return str(path)


def test_load_local_raster_success(sample_geotiff):
    result = load_local_raster(sample_geotiff)

    assert result.path == str(Path(sample_geotiff).resolve())
    assert result.metadata["width"] == 10
    assert result.metadata["height"] == 10
    assert result.metadata["crs"] == "EPSG:4326"


def test_missing_file():
    with pytest.raises(FileNotFoundError):
        load_local_raster("/missing/file.tif")


def test_manifest():
    assert PLUGIN.manifest.id == "local_raster_loader"

۱۲. مدیریت خطا

پلاگین باید خطاهای قابل فهم و مشخص ایجاد کند. خطاهای مبهم باعث می‌شوند trace و audit بی‌ارزش شوند.

نوع خطا زمان استفاده مثال
ValueError ورودی از نظر مقدار نامعتبر است مسیر خالی، radius منفی
FileNotFoundError فایل مورد نیاز وجود ندارد GeoTIFF پیدا نشد
RuntimeError پردازش در زمان اجرا شکست خورد فایل خراب یا عملیات ناموفق
SDKDependencyError کتابخانه مورد نیاز نصب نیست rasterio یا geopandas نصب نیست
SDKValidationError خطای اعتبارسنجی مرتبط با SDK امضای تابع ناسازگار

نمونه مدیریت خطا

from pathlib import Path

def validate_file_path(path: str) -> Path:
    if not path or not isinstance(path, str):
        raise ValueError("path must be a non-empty string")

    file_path = Path(path).expanduser().resolve()

    if not file_path.exists():
        raise FileNotFoundError(f"File not found: {file_path}")

    if not file_path.is_file():
        raise ValueError(f"Path is not a file: {file_path}")

    return file_path
بهتر است خطاها فارسی یا انگلیسی واضح باشند. مهم این است که trace و audit بعداً بتوانند علت شکست را توضیح دهند.

۱۳. Permissions و امنیت آینده

در معماری فعلی پلاگین‌ها trusted هستند، اما manifest باید permissions داشته باشد تا در آینده بتوان کنترل دسترسی، sandboxing و محدودیت منابع را اضافه کرد.

مجوزهای پیشنهادی

Permission کاربرد
read_raster خواندن فایل رستری
write_raster نوشتن خروجی رستری
read_vector خواندن داده برداری
write_vector نوشتن خروجی برداری
read_database خواندن از دیتابیس مثل PostGIS
write_database نوشتن در دیتابیس
network_access دسترسی به سرویس آنلاین مثل WMS/WFS/API
user_location دسترسی به موقعیت کاربر
long_running_job اجرای job طولانی یا async
اگر پلاگین به موقعیت کاربر نیاز دارد، باید صریحاً permission user_location را در manifest اعلام کند.

۱۵. نکات پیشرفته درباره رفتار داخلی SDK

۱۵.۱. SDKStepHandler چگونه آرگومان‌ها را می‌سازد؟

در زمان اجرا، SDK امضای تابع پلاگین را بررسی می‌کند و بر اساس annotation تصمیم می‌گیرد چه چیزی به تابع پاس بدهد.

نوع پارامتر رفتار SDK
RasterIn از artifact نوع raster_ref ساخته می‌شود.
VectorIn از artifact نوع features یا vector ساخته می‌شود.
ExecutionContext یا پارامتر context خود context تزریق می‌شود.
str / int / float / bool از step.parameters خوانده می‌شود.
پارامتر با مقدار پیش‌فرض اگر در step نبود، مقدار پیش‌فرض استفاده می‌شود.

۱۵.۲. SDKPlanner چگونه parameters می‌سازد؟

Planner تولیدشده توسط SDK معمولاً از entityهای QueryIR استفاده می‌کند: 

for entity in query_ir.entities:
    params[entity.role] = entity.name

پس اگر تابع شما پارامتر path دارد، بهتر است parser یا query_ir entityای با role="path" تولید کند.

در مراحل اولیه، برای تست مستقیم capability لازم نیست pipeline کامل را اجرا کنید. می‌توانید تابع را مستقیم در تست صدا بزنید.

۱۵.۳. چند capability در یک پلاگین

یک فایل پلاگین می‌تواند چند capability داشته باشد. auto_collect همه capabilityهایی را که قبل از آن تعریف شده‌اند جمع می‌کند. 

@capability(name="load_data")
def load_data(path: str):
    ...

@capability(name="validate_data")
def validate_data(path: str):
    ...

PLUGIN = auto_collect(
    id="data_tools",
    version="1.0.0",
)
اگر فایل‌های زیادی در یک پلاگین قرار می‌دهید، مراقب باشید وظایف بیش از حد نامرتبط نشوند. برای نگهداری بهتر، پلاگین‌ها باید هدفمند باقی بمانند.

۱۶. خطاهای رایج و راه‌حل‌ها

خطا علت احتمالی راه‌حل
ModuleNotFoundError: geochat_sdk SDK در venv نصب نیست نصب فایل whl مربوط به SDK
ModuleNotFoundError: geochat_kernel Kernel در venv نصب نیست یا wheel خالی ساخته شده بررسی site-packages و محتوای whl
PLUGIN not found متغیر PLUGIN در فایل پلاگین تعریف نشده در انتهای فایل PLUGIN = auto_collect(...) بگذارید
Capability ثبت نمی‌شود auto_collect قبل از @capability آمده auto_collect را به انتهای فایل منتقل کنید
Missing parameter نام پارامتر تابع با step.parameters هماهنگ نیست نام required_inputs، entity role و پارامتر تابع را هماهنگ کنید
Missing raster input تابع RasterIn می‌خواهد اما artifact رستری در inputs نیست قبل از آن local_raster_loader یا data source مناسب اجرا شود
rasterio is required وابستگی پلاگین نصب نیست pip install rasterio numpy
خروجی در پاسخ دیده نمی‌شود خروجی به نوع استاندارد تبدیل نشده از RasterOut یا VectorOut استفاده کنید

۱۷. چک‌لیست نهایی تحویل پلاگین

قبل از تحویل هر پلاگین، موارد زیر باید بررسی شوند:

چک‌لیست کد

  • فایل پلاگین در پوشه plugins/ قرار دارد.
  • نام فایل snake_case و معنادار است.
  • حداقل یک تابع با @capability تعریف شده است.
  • برای capability، name، keywords، required_inputs و output_kind مشخص شده‌اند.
  • در انتهای فایل PLUGIN = auto_collect(...) وجود دارد.
  • auto_collect بعد از همه capabilityها آمده است.
  • permissions مناسب در manifest ثبت شده‌اند.
  • ورودی‌ها validate می‌شوند.
  • خطاها واضح و قابل فهم هستند.
  • برای خروجی رستری از RasterOut استفاده شده است.
  • برای خروجی برداری از VectorOut استفاده شده است.
  • metadata کافی و مفید تولید شده است.

چک‌لیست تست

  • فایل تست در پوشه tests/ وجود دارد.
  • تست اجرای موفق نوشته شده است.
  • تست ورودی نامعتبر نوشته شده است.
  • تست manifest نوشته شده است.
  • اگر خروجی RasterOut یا VectorOut است، تبدیل به artifact تست شده است.
  • همه تست‌ها با pytest پاس می‌شوند.

چک‌لیست اجرایی

  • وابستگی‌های خارجی پلاگین نصب شده‌اند.
  • پلاگین باعث import error در startup سیستم نمی‌شود.
  • فایل‌های خروجی در مسیر output/ ذخیره می‌شوند.
  • پلاگین فایل ورودی کاربر را تغییر یا حذف نمی‌کند.
  • در صورت نیاز به دسترسی خاص، permission مربوطه اعلام شده است.
پلاگینی که این چک‌لیست را پاس کند، برای ورود به pipeline سیستم GeoChat آماده است.

۱۸. استاندارد پیشنهادی برای اولین پلاگین: local_raster_loader

اولین پلاگین پیشنهادی سیستم local_raster_loader است. این پلاگین باید یک مسیر فایل محلی GeoTIFF را بگیرد، آن را validate کند، متادیتای اصلی را استخراج کند و یک RasterOut برگرداند.

ویژگی‌های ضروری

  • پشتیبانی از پسوندهای .tif، .tiff، .geotiff، .vrt
  • بررسی وجود فایل
  • بررسی اینکه مسیر واقعاً فایل است نه پوشه
  • خواندن امن با rasterio.open
  • استخراج width، height، count، CRS، bounds، resolution، nodata و dtype
  • برگرداندن خروجی به شکل RasterOut
  • ثبت permission با read_raster

Capability Descriptor پیشنهادی

@capability(
    name="load_local_raster",
    keywords=[
        "raster",
        "geotiff",
        "tif",
        "tiff",
        "local raster",
        "load raster",
        "بارگذاری رستر",
        "خواندن رستر",
        "فایل رستر",
    ],
    required_inputs=["path"],
    output_kind="raster",
    description="Load a local raster file and return a raster reference",
    permissions=["read_raster"],
    metadata={"category": "data_io", "source_priority": 1},
)
